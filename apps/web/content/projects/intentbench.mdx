## Problem

For a text classification task there are three very different options: a classical model, a fine-tuned transformer, or an LLM prompted with no or few examples. They differ a lot in accuracy, speed and cost, and the right choice depends on all three, not just accuracy.

## What I'm building

A side-by-side comparison on **CLINC150** (`plus` configuration): short user queries labelled with **150 intents plus out-of-scope**.

- **TF-IDF + logistic regression** (scikit-learn). Done.
- **Fine-tuned DistilBERT** (PyTorch, Hugging Face Transformers). Done.
- **Zero-shot and few-shot LLM classification.** Planned.

The plan is to measure all approaches on one held-out test set for accuracy, macro-F1, p95 latency and cost per 1,000 requests, look at the most confused intent pairs, and serve the chosen model behind a FastAPI endpoint.

## Key decisions and trade-offs

- **The same data for every approach.** Comparing all models on the same splits is what makes the numbers comparable.
- **Choose hyperparameters on validation, report on test.** Each approach is tuned on the validation set (selected by macro-F1); the held-out test set is kept for the final comparison so it doesn't leak into model choice.
- **Measure cost and latency, not only accuracy.** A model that is slightly more accurate but much slower or more expensive per request may be the wrong thing to ship.
- **Plan for "I don't know".** The endpoint will validate input with Pydantic and use a confidence threshold, so queries the model is unsure about get an out-of-scope response instead of a confident wrong intent.
