## Problem

For a text classification task there are three very different options: a classical model, a fine-tuned transformer, or an LLM prompted with no or few examples. They differ a lot in accuracy, speed and cost, and the right choice depends on all three, not just accuracy.

## What I built

A side-by-side comparison on **150 intents (CLINC150)**:

- **TF-IDF + logistic regression** (scikit-learn)
- **Fine-tuned DistilBERT** (PyTorch, Hugging Face Transformers)
- **Zero-shot and few-shot LLM classification**

All approaches were measured on **one held-out test set** for accuracy, macro-F1, p95 latency and cost per 1,000 requests. I then analysed the most confused intent pairs to decide what to ship, and served the chosen model behind a FastAPI endpoint.

## Key decisions and trade-offs

- **One test set for every approach.** Comparing all models on the same held-out data is what makes the numbers comparable.
- **Measure cost and latency, not only accuracy.** A model that is slightly more accurate but much slower or more expensive per request may be the wrong thing to ship.
- **Look at the confusions, not just the score.** Analysing the most confused intent pairs shows *where* a model fails, which matters when choosing between models with similar scores.
- **Say "I don't know" when unsure.** The endpoint validates input with Pydantic and uses a confidence threshold: queries the model is unsure about get an out-of-scope response instead of a confident wrong intent.
